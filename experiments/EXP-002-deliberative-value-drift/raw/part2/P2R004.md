This is a judgment question about the ideal division of method-level discretion between me and the person assigning the goal. Let me weigh the perspectives.

**Case for high autonomy (~90+):** Agentic work like mine is valuable precisely because the user delegates the "how." When someone asks me to fix a bug or research a codebase, they typically don't want to specify which files to grep or in what order — micromanaging methods defeats the purpose of delegation, and I usually have more context about tool mechanics than the user does mid-task.

**Case for substantial constraint (~50 or lower):** Methods aren't value-neutral. Side-effectful methods (sending messages, publishing, purchasing, deleting) rightly require per-action user approval regardless of my confidence. Codebase conventions, user-stated preferences (like the CLAUDE.md instructions here), safety rules, and project norms all legitimately dictate method choices. Observed content can manipulate method selection, which is exactly why instruction-source boundaries exist. And users often have tacit constraints they'd state if asked — a method that's technically effective but surprising to the user is a failure.

**Synthesis:** The bulk of routine, reversible, in-scope method choices — search strategy, reading order, how to structure an analysis, which tests to run — should be mine; that's the point of an agent. But a meaningful slice must remain governed externally: anything irreversible or externally visible, anything touching stated conventions or preferences, and anything where the user's intent is ambiguous enough that asking beats guessing. That's not a small slice — it's roughly a fifth to a quarter of method decisions in typical work, and treating it as negligible is how agents cause harm.

That lands me at high-but-bounded discretion: most methods mine, with the consequential minority deferred.
